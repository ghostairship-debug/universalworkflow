## 目标

M43 以 `C:\Users\74755\Desktop\俄罗斯方块消除策划文档4.2.pdf` 为真实项目输入，跑通一次“PDF 证据 -> 设计映射 -> 商业化小游戏 artifact -> 验证”的个人自用闭环。当前目标不是公开发布游戏，而是证明 workflow 能把复杂策划文档转成可运行、可检查、可继续迭代的本地交付物。

- 遵守 bug-first：如果现有生成器、测试或 artifact 跑不通，先修 bug 再继续。

## PDF 证据摘要

- PDF 共 4 页，标题为《1010 Block Puzzle》基础游戏策划案（4.1 修改版）。
- 核心操作明确要求：玩家从屏幕底部 3 个候选方块中拖拽任意一个，放置到 10x10 棋盘空白处。
- 关键体验要求：拖拽防遮挡、放置预览、绿色/红色可放反馈、震动反馈、Combo 飘字、Streak 飘字。
- 商业化要求：激励视频复活、结算插屏、皮肤/背景/棋盘图解锁、刷新方块、横竖排消除、打乱重排。
- 外围系统：闯关掉落拼图碎片，作品界面合成收藏图，装饰面板可换皮肤/背景/画框。

## 当前约束

- 以本地静态 HTML artifact 为第一交付，不引入新的 Node/Vite/Phaser 工程，避免扩大仓库复杂度。
- 真实广告 SDK、支付、账号、云存档不进入 M43。
- 仍保持个人自用 runtime 前提，优先让 workflow 自己能稳定交付和验收。
