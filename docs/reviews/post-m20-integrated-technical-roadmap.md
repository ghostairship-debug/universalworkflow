# Post-M20 Integrated Technical Roadmap

## Current Position

After `M20`, the repository now ships:

- local-first runtime semantics with repository-owned truth
- semi-automatic workflow-driven development with bounded repo mutation
- built-in Web operator UI plus CLI and API operator surfaces
- remote HTTP worker pools with fenced callback ownership
- formal `project_delivery` orchestration
- majority-quorum scheduler-authority peers, committed cross-control-plane lease ownership, and takeover lineage

## Mainline Status

The mainline product is now `v1 core complete`.

- `TD-021` is retired
- no open structural debt remains on the control-plane mainline
- future work should not reopen the core runtime path without an explicit new rebaseline

## Recommended Next Cycle

`M21` should begin with a post-`M20` rebaseline and choose only among breadth tracks such as:

1. deeper workflow autonomy and self-hosted development execution
2. selective ecosystem expansion
3. multimodal / provider breadth once it has a clear product need

## Route Synthesis

The best route after `M20` is to preserve the current repository as the core-complete control-plane product, keep the `M19-M20` cluster semantics intact, and treat any `M21+` work as additive breadth rather than unfinished mainline closure.
