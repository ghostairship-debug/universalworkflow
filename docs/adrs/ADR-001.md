# ADR-001: Fixed Control Loop

## Context

M0 needs a stable control surface before the project expands into richer execution behaviors.

## Decision

Use a fixed control loop with explicit phases and events. The system is orchestrator-led, not graph-led.

## Alternatives considered

- Let the runtime graph own the main system semantics.
- Allow each preset to define a different control loop.

## Consequences

- Positive:
  The system remains predictable and testable in M0.
- Negative:
  Advanced runtime flexibility is postponed to later phases.
